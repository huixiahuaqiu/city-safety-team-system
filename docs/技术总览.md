## 1. 系统定位与目标

**系统名称：** 城市安全数智创新团队文献管理系统（工作台 + 对外门户）

**服务对象：** 高校科研团队（导师 / 组长 / 学生 / 访客）

**核心目标：**

- 统一管理团队成员、科研项目、成果台账与资源文件
- 支持请假审批、任务、周报等日常协作
- 提供文献库、数据集、报告归档、共享文件等资源能力
- 集成 AI 对话、文献对比、Excel/文档解析、标注与训练台账
- 支持本地优先（`localStorage`）与可选云端（Supabase）双写同步
- 同一 SPA 内同时承载「登录工作台」与「对外门户页」

**产品形态：** 单页应用（SPA）。页面壳在 `123123/index.html`，业务 UI 以懒加载 HTML 片段形式注入。

## 2. 技术栈总览

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 UI | HTML5 + CSS3 + 原生 JavaScript | **非 React 运行时**；`package.json` 中 Vite/React 依赖为历史/可选路径 |
| 样式 | `css/app-shell.css`、`css/portal-public.css`；本地 Tailwind Play CDN 构建（`vendor/tailwind`） | 工作台与门户分区样式 |
| 图表 | ECharts | 首页看板、门户统计、文献对比可视化 |
| Excel | SheetJS（`vendor/xlsx`，经 `vendor-lazy.js` 懒加载） | 导入导出、Excel 智能分析 |
| 文档 | PDF.js、mammoth、Cropper、wangEditor | PDF/Word 解析、图片裁剪、富文本 |
| 云端库 | Supabase PostgREST（PostgreSQL） | 真实表：`patents`、`papers`；KV 同步伪行亦落在 patents |
| AI | 阿里云百炼（通义系列） | 对话、分析类能力；Key 存浏览器侧 |
| 生产网关 | Python 标准库 HTTP：`working_proxy.py`（默认端口 **8000**） | 静态资源 + `/api/*` |
| 可选 Node 代理 | `server.cjs` / `proxy_server.js` | 历史或备用路径 |
| 对象存储 | 本地磁盘 / 可选 MinIO（S3 兼容） | 共享文件、大体量资源 |
| 进程守护 | systemd + Nginx | 见 `deploy/` |

**心智模型：**

```
浏览器 SPA (index.html)
  ├─ config.js → config.local.js
  ├─ modules/*.html  ← module-loader + __MODULE_VERSIONS
  ├─ localStorage  ↔  cloudUpsert / pullAllFromCloud  →  Supabase
  └─ /api/*  →  working_proxy.py（上传、MLOps、OCR、共享/数据集、百炼代理等）
```

## 4. 运行与启动方式

### 4.1 推荐：一键启动

```bash
cd 123123
python start_web.py
```

行为概要：

1. 切换到 `123123/` 目录
2. 尽量执行 `build_assets.build()`（刷新 `?v=` 与 `module-manifest.js`）
3. 启动 `working_proxy.run_server(8000)`
4. 自动打开 `http://localhost:8000`（生产可设 `CITYSAFE_NO_BROWSER=1`）

相关环境变量：

| 变量 | 作用 |
|------|------|
| `CITYSAFE_NO_BROWSER=1` | 不弹浏览器（systemd 无头环境） |
| `CITYSAFE_SKIP_BUILD=1` | 跳过启动时的资源哈希构建（按脚本约定） |

### 4.2 仅静态预览

可直接打开 `index.html`，本地 `localStorage` 功能可用；依赖网关的上传、部分 AI 代理、对象存储等能力会受限。

### 4.3 生产

- 单元：`deploy/systemd/citysafe-gateway.service`
- 反向代理：Nginx（`deploy/` 下配置）
- 发布：`deploy/scripts/release.sh`（制品化，生产启动不再现场构建）

## 5. 前端架构与模块加载

### 5.1 SPA 壳

`index.html` 负责：

- 登录区与会话恢复
- 侧栏导航（`onclick="showModule('moduleId')"`）
- 门户页（介绍 / 成果 / 项目 / 成员 / 联系）内联宿主
- 各业务模块空壳：`<div id="xxx" class="module" data-lazy="1">`

### 5.2 懒加载流水线

| 步骤 | 组件 | 说明 |
|------|------|------|
| 1 | `showModule(moduleId)`（`js/app-core.js`） | 切换可见模块、权限校验后加载 |
| 2 | `loadModuleHtml(moduleId)`（`js/module-loader.js`） | 请求 `modules/{id}.html?v={hash}` |
| 3 | `window.__MODULE_VERSIONS`（`js/module-manifest.js`） | 由 `build_assets.py` 按内容哈希生成，精准缓存控制 |
| 4 | 注入 DOM、`data-loaded="1"` | 随后调用各模块 `initXxx()` |
| 5 | 悬停预取 | `prefetchModuleHtml` 降低首开延迟 |

辅助 API：`forceReloadModuleHtml`、`__moduleHtmlCache`。

### 5.3 脚本加载顺序（摘要）

**Head：** ECharts → Tailwind → 字体 → 壳 CSS → `vendor-lazy.js`

**Body 末尾（依赖顺序）：**

1. `config.js` → `config.local.js`（`Object.assign` 覆盖，禁止整对象替换）
2. `module-manifest.js` → `module-loader.js`
3. `app-core.js`（Supabase、云同步、`showModule`、通用工具）
4. `excel-tools.js` → `achievements-modules.js` → `my-projects.js` → `my-achievements.js`
5. `app-legacy-a.js` / `app-legacy-b.js` 及各功能包（文献、数据集、竞赛、申请中心、门户等）

所有本地 `js/`、`css/` 引用带内容哈希查询串 `?v=<sha1前10位>`。

### 5.4 主要脚本职责

| 文件 | 职责 |
|------|------|
| `module-loader.js` / `module-manifest.js` | 懒加载与版本清单 |
| `app-core.js` | 配置读取、Supabase REST、云 KV、模块切换、公共工具 |
| `app-legacy-a.js` | 软著台账、部分初始化胶水 |
| `app-legacy-b.js` | 认证权限、任务周报、通知会议、备份日志、训练/标注/对话等大块逻辑 |
| `achievements-modules.js` | 项目三表、成员、专利/论文/标准 + **通用列头筛选** |
| `my-projects.js` / `my-achievements.js` | 「我的项目 / 我的成果」聚合视图 |
| `literature-*.js`、`dataset-library.js`、`shared-file-library.js`、`project-report.js` | 资源中心 |
| `competition-management.js`、`application-center.js`、`holiday-leave.js` | 竞赛、申请与请假 |
| `home-dashboard-p3.js`、`portal-public.js` | 首页看板与对外门户 |
| `vendor-lazy.js` | 按需加载 xlsx / pdf / mammoth 等重型库 |

## 6. 配置体系

采用「可提交公开配置 + 本机私密覆盖 + 服务端环境变量」三层：

| 文件 | 是否入库 | 用途 |
|------|----------|------|
| `config.js` | 是 | `window.APP_CONFIG` 公开默认（如 Supabase URL/可发布 Key） |
| `config.example.js` | 是 | 复制为 `config.local.js` 的模板 |
| `config.local.js` | **否** | Token、本机密钥；`Object.assign` 合并 |
| `.env.example` | 是 | 服务端变量模板 |
| `.env` | **否** | 网关：上传限额、MinIO、ClamAV、`BIND_HOST`、CORS、各类 Token |

前端读取：`getAppConfig(key, fallback)`（`app-core.js`）。

常见本机覆盖项（见 `config.example.js`）：`MLOPS_TOKEN`、`ANNOTATION_UPLOAD_TOKEN`、`DATASET_UPLOAD_TOKEN`、存储桶名等。

## 7. 账号、角色与权限

**实现重心：** `js/app-legacy-b.js`

### 7.1 角色

| 角色代码 | 含义 |
|----------|------|
| `admin` | 导师 / 系统管理员（矩阵中恒为通过） |
| `leader` | 组长 |
| `student` | 学生 |
| `visitor` | 访客 |

展示名由 `ROLE_LABELS` 映射。

### 7.2 账号与会话

- 账号数据：`accountData`（localStorage + 云同步）
- 字段含：学号/工号、角色、状态、密码哈希或明文策略字段等
- 会话：`currentSession`，默认约 24 小时（`TOKEN_EXPIRE_MS`）
- 当前用户挂到 `window.currentUser`
- 登录失败锁定：`loginAttempts`；密码策略：`passwordPolicy`
- 演示填充：`fillLoginDemo(...)`

> 演示/引导场景可能存在默认口令约定，生产部署必须修改并关闭不安全的演示入口。

### 7.3 权限矩阵

- 结构：`permissionMatrix` — 行形如 `[功能名, admin, leader, student, visitor]`
- 判定：`hasPermission(featureName)`
- UI：`applyRolePermissions()` 按模块隐藏侧栏 `.nav-item`

典型能力维度（节选）：首页；成员档案（全组/仅自己/编辑）；任务与周报（查看/提交/审核）；请假（提交/本组审批/全部/流程配置）；项目与成果（查看/编辑）；智能工具；资源中心；账号管理；系统设置；操作日志；数据备份。

角色矩阵 UI 模块：`role_permission`；账号管理模块：`account_permission`。

## 9. 数据层与云端同步

### 9.1 存储策略

| 层级 | 机制 |
|------|------|
| 浏览器本地 | `localStorage` 存 JSON（离线/演示仍可用） |
| **生产主路径** | 网关 `DATA_BACKEND=postgres`：`/api/sync` 读、`/api/sync/upsert` 写 → PostgreSQL `app_sync` |
| 兼容路径 | 未启用网关数据后端时，可走 Supabase KV 伪行（`__APP_SYNC__` / `__SYNC_KV__{key}`） |
| 真实业务表 | `patents`、`papers` 经网关 `/api/data/records` 或历史 Supabase REST |
| 大文件 | 网关磁盘 / IndexedDB 分块 / MinIO 预签名；元数据进 KV |
| 自动上行 | `localStorage.setItem` → 防抖 `queueCloudUpsert`（约 350ms）；按登录主体分 outbox |
| 下行轮询 | 首页约 5s，其他页约 10s；`/api/sync/versions` 轻量探测；切回前台/上线立刻拉；指数退避；跨标签 `storage` |

更细说明：`123123/云端同步说明.md`、`deploy/RUNBOOK.md`。

### 9.2 同步授权（前后端双重门禁）

| 位置 | 文件 | 规则 |
|------|------|------|
| 前端预检 | `js/app-core.js` | `CLOUD_KEY_WRITE_FEATURES` + `permissionMatrix`；学生仅允许有行级归属的键 |
| 服务端强制 | `sync_policy.py` ← `working_proxy.py` | `can_read` / `can_write` / `validate_value` / `filter_read_value` / `merge_scoped_write` |

要点：

- **账号与审计**：`accountData`、`loginLogData`、`operationLogData` 不由浏览器整表回写；账号验证器与审计日志由服务端持有
- **学生行级隔离**：`taskData`、`weeklyReportData`、`applicationData`、`annotationData` 读取只见本人行；写入经 `merge_scoped_write` 保留他人行，禁止抢占他人 `id`
- **乐观锁**：`baseVersion` compare-and-swap；冲突返回 `409`；前端按 outbox `revision` 标记冲突，避免误冻较新的本地修改
- **权限矩阵**：写权限跟 `permissionMatrix` 功能位对齐（如「成果管理（编辑）」「资源中心（上传/编辑）」）；管理员恒可写（审计键除外）
- **首次改密门禁**：`/api/auth/me` 返回权威 `mustChangePwd`；未改密会话仅可访问改密相关接口（其他业务 API 返回 `403 password_change_required`）

## 10. 通用列头筛选机制

为统一「去掉列头排序箭头、改为 Excel 式 ▼ 选值筛选」而设计，定义于 `js/achievements-modules.js` 文件顶部。

### 10.1 核心 API

| 函数 | 作用 |
|------|------|
| `acShowColFilter(event, key, field, label, fullArr, renderFnName)` | 弹出该列去重取值 + 条数；点选后触发重渲染 |
| `acColRows(key, arr)` | 按当前列筛选过滤数组（多列 AND，不改原数组） |
| `acSetColFilter` / `acClearColFilter` | 设置 / 清空 |
| `acUpdateColIndicators` | 刷新按钮样式（激活为 `▼●`） |
| `acColValFn(key, field, fn)` | 注册虚拟列取值（如「年度」取日期前 4 位） |

### 10.2 DOM 约定

表头使用：

```html
<span data-acfilter="{key}" data-acfield="{field}"
      onclick="openXxxColFilter(event,'{field}','{标签}')"
      title="按此列筛选">▼</span>
```

与顶部筛选面板、侧栏筛选可叠加：先面板过滤，再在结果上套 `acColRows`。

### 10.3 已接入表

| Filter key | 打开函数 | 渲染函数 / 模块 |
|------------|----------|-----------------|
| `longitudinal` | `openLongitudinalColFilter` | `renderLongitudinalTable` |
| `horizontal` | `openHorizontalColFilter` | `renderHorizontalTable` |
| `school` | `openSchoolColFilter` | `renderSchoolTable` |
| `paper` | `openPaperColFilter` | `renderPaperTable` |
| `standard` | `openStandardColFilter` | `renderStandardTable` |
| `patent` | `openPatentColFilter` | `renderPatentMgmtTable` |
| `copyright` | `openCopyrightColFilter` | `renderCopyrightTable`（`app-legacy-a.js`） |
| `myprojects` | `openMpColFilter` | `mpRender`（`my-projects.js`） |
| `myachievements` | `openAchColFilter` | `achRender`（`my-achievements.js`） |

虚拟列示例：`year` ← `startDate` / `publish_date` / `regDate`；论文 `publishDate` ← `publish_date`；我的项目 `funding` 按展示格式 `toFixed(2)`；我的成果 `info` ← `journal || status || authors`。

竞赛成果为卡片流，未纳入本表头体系。

## 14. 构建、缓存与部署

### 14.1 `build_assets.py`

- 扫描 `index.html` 中本地 `js/`、`css/` 引用，按**文件内容 SHA1** 重写 `?v=`
- 扫描 `modules/*.html`，生成 `js/module-manifest.js` 中的 `__MODULE_VERSIONS`
- `python build_assets.py --check`：有差异则非 0 退出（适合 CI）
- 幂等：内容不变则不产生无谓 git 变更

### 14.2 容器化一键栈（生产主路径）

| Compose | 用途 |
|---------|------|
| `deploy/compose.yaml` | 基座：`db` + `migrate` + `minio` + `minio-init` + `gateway` + `edge` |
| `deploy/compose.local.yaml` | 本机回放：仅绑定 `127.0.0.1:8080`，不暴露 DB/MinIO/网关端口 |
| `deploy/compose.server.yaml` | 公司服务器：80/443、强制认证、TLS 证书卷 |

本机入口：`deploy/scripts/stack.ps1`；服务器远端发布：`deploy/scripts/deploy-server.ps1` → `bootstrap-server.sh`。

边缘 Nginx：`config.js` / `config.local.js` **一律映射为容器生成的公开 `config.runtime.js`**（禁止把本机密钥文件打进镜像）。CSP 已切强制模式；MinIO 仅经 `/minio-upload/` 预签名路径暴露。

维护锁：发布、备份、隔离恢复验证共用 `/run/lock/citysafe/maintenance.lock`（root 私有）。定时任务模板：`deploy/cron/citysafe.cron`。

## 15. 安全与生产硬化

对齐仓库规则「生产级实现标准」，实践包括：

1. **禁止入库密钥**：`.env`、`config.local.js`、上传目录、日志、缓存均在 `.gitignore`
2. **配置模板齐全**：`.env.example`、`config.example.js`、deploy 下 `*.example`
3. **上传加固**：大小/类型/路径校验；可选杀毒扫描；MinIO 预签名边缘 `client_max_body_size` 有上限，确认时校验/删除超限对象
4. **Token 比对**：服务端使用恒定时间比较（如 `secrets.compare_digest`）；网关会话模式下标注上传走 Bearer，不必再配浏览器侧 `ANNOTATION_UPLOAD_TOKEN`
5. **绑定与 CORS**：生产建议 `BIND_HOST=127.0.0.1`，由 Nginx 对外；收敛 `CORS_ALLOW_ORIGIN`
6. **审计与限流归属**：登录失败计数与审计优先使用可信代理头中的真实客户端 IP（`TRUSTED_PROXY_IPS` / 默认私网）
7. **XSS**：展示用户/云端字符串统一走 `escapeHtml` / `window.escapeHtml`
8. **接口**：新增 API 需校验、错误响应、权限与必要审计；强制改密完成前限制业务写接口
